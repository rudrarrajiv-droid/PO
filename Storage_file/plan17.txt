============================================================
PHASE 8 OBJECTIVE
============================================================

Create a clear PO HISTORY view.

For every PO, the user must be able to see:

1. PO creation information
2. IN transactions
3. OUT transactions
4. Date-wise movement
5. Quantity
6. Running balance
7. User who performed the transaction
8. Remarks, when available

The purpose is to answer:

"Is PO ke saath ab tak kya-kya movement hua hai?"

============================================================
STEP 1 — HISTORY ACTION
============================================================

Add a:

VIEW HISTORY

action to the existing PO interface.

The action must open history for the SELECTED PO only.

Do NOT create a separate history for every customer.

Do NOT create a separate database collection for history.

Use the existing:

poTransactions

collection.

============================================================
STEP 4 — DATE ORDER
============================================================

Transactions must be shown chronologically.

Default:

Oldest → Newest

The latest transaction should therefore appear at the bottom of the
chronological list.

If the existing UI already uses newest-first history:

follow the existing application convention, but the running balance
must remain mathematically correct.

Do NOT modify transaction dates.

============================================================
STEP 5 — RUNNING BALANCE
============================================================

Calculate the running balance from the transaction history.

Starting point:

OPN QTY

For every IN:

Running Balance = Previous Balance + IN Quantity

For every OUT:

Running Balance = Previous Balance - OUT Quantity

Example:

Opening Qty = 1000

IN = 500

Balance = 1500

OUT = 200

Balance = 1300

IN = 100

Balance = 1400

The final running balance must match the current PO CLOSING BAL.

============================================================
STEP 6 — DO NOT TRUST STORED BALANCE BLINDLY
============================================================

History display must be based on actual transaction records.

Do not blindly display a manually stored running balance if transaction
history provides enough information to calculate it.

If calculated history balance does NOT match the current PO Closing
Balance:

DO NOT silently correct the database.

Show/report the mismatch.

Example:

"History balance mismatch detected."

Do NOT modify data automatically.
