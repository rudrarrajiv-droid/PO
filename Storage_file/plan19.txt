============================================================
STEP 1 — STATUS CALCULATION
============================================================

Use the existing PO data.

The primary quantity logic is:

CLOSING BAL
=
OPN QTY + TOTAL IN - TOTAL OUT

Do NOT change this formula.

============================================================
STEP 2 — COMPLETED STATUS
============================================================

A PO should be considered:

COMPLETED

when its Closing Balance reaches zero.

Example:

OPN QTY = 1000

IN = 0

OUT = 1000

CLOSING BAL = 0

Status:

COMPLETED

Do not mark a PO as completed merely because its Delivery Date has
passed.

============================================================
STEP 3 — PENDING STATUS
============================================================

A PO should be:

PENDING

when:

CLOSING BAL > 0

and it is not otherwise classified as overdue according to the rules
below.

============================================================
STEP 4 — PARTIALLY COMPLETED
============================================================

A PO should be:

PARTIALLY COMPLETED

when:

CLOSING BAL > 0

AND

some quantity has already been fulfilled/issued through OUT transactions.

Example:

OPN QTY = 1000

OUT = 400

CLOSING BAL = 600

Status:

PARTIALLY COMPLETED

Do not classify a PO as partially completed merely because it has an IN
transaction.

Use the actual PO movement logic already established.

============================================================
STEP 5 — OVERDUE / DELAYED
============================================================

A PO may be:

OVERDUE / DELAYED

only when:

Delivery Date has passed

AND

Closing Balance > 0

Example:

Delivery Date = yesterday

Closing Balance = 500

Status:

OVERDUE / DELAYED

If Closing Balance = 0:

DO NOT mark it overdue.

It remains:

COMPLETED

============================================================
STEP 6 — DELIVERY DATE
============================================================

Use the actual:

DELIVERY DATE

stored in the PO.

Do NOT modify the date.

Do NOT automatically extend the date.

Do NOT create a new date.

Use the application's existing date/time handling.

Be careful with timezone conversion.

The comparison must use the business/local date consistently.

============================================================
STEP 7 — STATUS PRIORITY
============================================================

Use this priority when multiple conditions are true:

1. COMPLETED
2. OVERDUE / DELAYED
3. PARTIALLY COMPLETED
4. PENDING

This means:

If Closing Balance = 0:

COMPLETED

even if Delivery Date has passed.

If Closing Balance > 0 and Delivery Date has passed:

OVERDUE / DELAYED

If Closing Balance > 0 and some OUT quantity exists before the deadline:

PARTIALLY COMPLETED

Otherwise:

PENDING
